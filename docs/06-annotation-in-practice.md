# 06 · 真实项目里的标注实战

手工精标（尤其是多边形、语义涂色、关键点、深度）**非常慢且贵**。  
真实项目几乎从不「全员从零画完所有像素」，而是：

> **预标注 → 人改难例 → 再训练 → 再预标注**（人机回环）

相关名词见：[术语表 glossary.md](./glossary.md)（含 **SAM / SAM2**、主动学习、伪标签等）。

---

## 1. 先回答三个问题（开工前）

在画第一张框之前，写在文档里：

| 问题 | 为什么重要 | 示例答案 |
|------|------------|----------|
| **业务要什么输出？** | 决定任务类型与标注成本 | 「只要报警有人」→ 检测即可，不必分割 |
| **上线场景长什么样？** | 避免域差异 | 夜间厂房摄像头、俯拍 45°、雾天 |
| **预算与工期？** | 决定自标 / 外包 / 合成 / 买数据 | 2 周内要 MVP → 先 200 张检测框 |

**成本直觉（相对，同分辨率同数量级）：**

```text
分类（分文件夹） < 检测框 < OBB < 姿态关键点 < 实例多边形 ≈ 语义涂色 << 深度真值
```

能用便宜任务解决问题，就不要上更贵的标注。

## 2. 标准产线（建议默认照这个做）

```text
① 写标注规范（Label Spec）
② 采集合格原始数据（去糊、去重、覆盖场景）
③ 人工精标「种子集」Seed Set（50～300 张，按任务）
④ 训练第一版小模型（n/s 即可）
⑤ 用模型（或 SAM）对剩余数据预标注
⑥ 人工只改错的 / 难的；抽检质检 QC
⑦ 合并版本 → 重训 → 回到 ⑤
⑧ 冻结一版数据与权重，再谈上线指标
```

### 2.1 标注规范要写清什么

没有规范，三人标三样，模型学乱：

- 类别列表与中英文名、**合并/拆分类**规则（「小轿车」和「SUV」是否一类）  
- 最小目标：边长 &lt; N 像素是否标  
- 遮挡：遮住 &gt;50% 是否仍标；只露一点怎么处理  
- 截断：贴边物体是否标  
- 难例：反光、模糊、密集重叠示例图（正面 / 反面各几张）  
- 导出格式：YOLO detect / seg / pose / OBB …  

### 2.2 种子集怎么选

不要只选「好拍好看」的图，要覆盖：

- 光照：亮 / 暗 / 逆光  
- 距离：近景大目标 / 远景小目标  
- 密度：单目标 / 拥挤  
- 负样本：无目标场景（降低误报）  

比例经验：Train:Val ≈ 8:2；Val 必须含难例，否则 mAP「很好」上线却崩。

### 2.3 质检（QC）怎么做

| 手段 | 做法 |
|------|------|
| 抽检 | 每批随机抽 5%～10%，错误率超阈值整批返工 |
| 双标 | 关键类别两人独立标，算一致性 |
| 模型找茬 | 用当前 best 权重推理，专查漏标、错类、框飘 |
| 可视化墙 | 每周把最差 50 张贴出来开会改规范 |

## 3. 按任务：实际怎么标（越具体越好）

### 3.1 分类 Classify —— 最便宜

**做法：**

1. 建文件夹：`train/ok`、`train/ng`、`val/ok`、`val/ng`  
2. 人把图拖进对应文件夹（或用脚本按规则粗分再抽检）  
3. 不要为分类去画框（除非后续还要定位）

**加速：**

- 先用 ImageNet / 旧模型 Top-1 粗分，人只改错的  
- 近重复图片去重，避免「看起来有 5000 张其实就 800 张」

**坑：** 背景主导（厂房都一样）→ 模型看背景不看缺陷；需要裁剪 ROI 或上检测。

---

### 3.2 检测 Detect —— 项目里最常见

**手工：** LabelImg / CVAT / Label Studio / Roboflow 画水平框，导出 YOLO。

**真实加速组合（推荐默认）：**

1. 用 `yolo11n.pt` 或同领域旧模型 **预标注** 全量图  
2. 导入 CVAT / Roboflow，人 **只改漏检、误检、框不准**  
3. 训一版 → 再预标下一批新图  

**经验量级（单类～少类、场景不太野）：**

| 阶段 | 精标量级 | 目的 |
|------|----------|------|
| MVP | 100～300 张 | 跑通业务演示 |
| 可用 | 500～2000 张 | 开始可控误报/漏报 |
| 打磨 | 持续主动学习加难例 | 压长尾 |

**主动学习示例流程：**

1. 模型对未标注池推理  
2. 按「最高置信却被业务判错」或「置信在 0.3～0.6 灰色地带」排序  
3. 每天只人工处理 Top 100 难图  
4. 合入数据集重训  

这样往往比「按文件名顺序接着标 2000 张简单图」更划算。

---

### 3.3 实例分割 Segment —— 别从零描多边形

纯手工描轮廓极慢。产线常见：

#### 方案 A：检测框 + SAM（最常用）

```text
YOLO 检测出框
    → 框作为 prompt 送给 SAM / SAM2
    → 得到 mask
    → 人只修边缘和漏割
    → 导出 YOLO-seg（多边形或 mask）
```

适合：商品抠图、行人轮廓、零件面积。

#### 方案 B：SAM2 视频传播

```text
视频第 1 帧：点一下或框一下目标
    → SAM2 向后传播 mask
    → 每隔 N 帧人工看一眼纠错
```

适合：监控视频里持续出现的同一类物体。

#### 方案 C：直接微调 `-seg`，用粗标签迭代

先接受「框内矩形 mask」或粗多边形 → 训一版 → 模型辅助变细。

**不建议：** 第一天就要求标注员精修到像素完美再开训（成本爆炸、进度为零）。

---

### 3.4 语义分割 Semantic —— 涂色贵，靠预分割 + 规范

**真值形态：** 与图同尺寸的单通道 PNG，像素值 = 类别 ID（`255` 常 ignore）。

**实战：**

1. 能用公开集（Cityscapes、ADE20K）微调就先微调，再采本域数据  
2. 用现成语义模型 / `-sem` 权重预生成类别图，人用画笔 **改错区域**  
3. 类别要克制：上线要 3 类就别标 19 类  
4. 边界（路沿、车道线）单独写规范，并在高 `imgsz` 下检查  

**视频：** 关键帧精修 + 光流/传播工具减少逐帧涂色（工具链因团队而异）。

---

### 3.5 姿态 Pose —— 预标关键点再改

**手工：** 在 CVAT 等工具里框人 + 点关节，导出 YOLO-pose。

**实战：**

1. 用 `yolo11n-pose.pt` 预推理得到框和关键点  
2. 人删除幽灵人、补遮挡点、修正左右肩腿接反  
3. 自定义骨架（非 COCO 17 点）成本高：先确认业务是否真需要新骨架  

**视频：** 可结合跟踪，减少「每一帧重新点人」；遮挡严重帧允许标可见性为不可见，而不是瞎猜。

---

### 3.6 OBB 旋转框 —— 工具要支持旋转

**手工：** Roboflow / CVAT 等开旋转矩形，贴合物体长边。

**实战：**

1. 航拍等可用遥感预训练 OBB 模型预标注  
2. 角度周期性容易标乱：规范里写清角度范围与「长边朝向」约定  
3. 若水平框 IoU 已经够业务用，**不要为了炫技上 OBB**

---

### 3.7 深度 Depth —— 基本不靠人手画

| 真值来源 | 说明 |
|----------|------|
| 深度相机（ToF / 结构光 / 双目工业套件） | 室内近距常见 |
| 双目立体匹配 | 需标定 |
| LiDAR 投影到相机 | 自动驾驶常见，有标定与同步成本 |
| 仿真引擎 | 自动完美深度，注意域差异 |
| 伪深度 / 多模型蒸馏 | 研究或冷启动，要谨慎当 GT |

**学习项目：** 直接用 `yolo26n-depth.pt` 推理即可。  
**产品项目：** 先解决传感器与标定，再谈训自己的深度网；把「人手涂深度图」当成基本不可行。

## 4. SAM / SAM2 在标注里怎么用（具体）

### 4.1 它们是什么

- **SAM**：给提示（点、框、粗 mask）→ 出分割 mask。擅长「把这个东西抠出来」，**不负责**给你业务类别名。  
- **SAM2**：更强视频能力，一帧提示后可在时间上跟踪传播。  

详见 [glossary.md · SAM / SAM2](./glossary.md)。

### 4.2 和 YOLO 的分工

| 组件 | 负责 |
|------|------|
| YOLO detect / 人工框 | 「哪里有个待抠目标」+ 类别 |
| SAM / SAM2 | 「这个目标的轮廓像素」 |
| 人 | 改类别、改漏误、修难看边缘 |

类别仍然来自检测模型或人工；SAM 解决的是 **轮廓劳动力**。

### 4.3 推荐落地步骤（图片实例分割）

1. 用本仓库检测脚本或自训检测模型跑全量图，导出框  
2. 对每个框调用 SAM（Ultralytics 也提供 SAM 接口）生成 mask  
3. 把 mask 转成 YOLO-seg 多边形 txt  
4. 导入标注工具，只展示「模型自信低」或「面积异常」的样本给人改  
5. 用修好的数据训 `yolo11n-seg.pt`，逐步少依赖 SAM  

### 4.4 视频步骤（SAM2）

1. 抽关键帧人工确认目标 ID  
2. SAM2 传播  
3. 每隔 K 帧抽检；漂移则在该帧重新提示  
4. 导出后再映射到训练格式  

### 4.5 局限（避免神话化）

- 透明、线状、极度粘连物体仍可能糊  
- 提示错了，mask 也会错  
- SAM mask **没有**业务类名，流水线要自己接类别  
- 全自动无审核会把系统误差写进训练集（越训越歪）

## 5. 外包 vs 自建 vs 平台

| 模式 | 适合 | 注意 |
|------|------|------|
| 自己标 | 种子集、规范探索、隐私数据 | 算清时薪；别让算法同学全职描点 |
| 外包众包 | 检测框大规模 | 必须有规范、试标、质检、抽检条款 |
| SaaS 平台（Roboflow 等） | 小团队要速度 | 数据出域与费用；导出格式核对 |
| 合成数据 | 危险场景、稀有缺陷、深度/关键点 | 留真实 Val；防过拟合仿真纹理 |

**试标流程（外包必做）：**

1. 发 20～50 张 + 规范  
2. 收回后算法与业务一起打分  
3. 不合格重训标注员或换商  
4. 再放开量

## 6. 版本管理（数据也要像代码一样）

建议每份数据集有：

```text
datasets/
  my_det_v0.1_seed/
  my_det_v0.2_prelabel_fix1/
  my_det_v0.3_qc_passed/
```

并记录：

- 图片数量、类别分布、来源相机  
- 标注工具与导出脚本版本  
- 对应训练出的 `best.pt` 与指标  
- 已知问题列表（「夜间漏检尚未加数据」）  

随便覆盖旧标签却不备份，出了问题无法回滚。

## 7. 小团队 30 天示例（检测为主）

| 天数 | 动作 |
|------|------|
| D1–D2 | 定任务=检测；写规范；定 3 个类 |
| D3–D5 | 采集 500 张；去糊去重；划 Val 100 张 |
| D6–D8 | 人工精标种子 150 张；训 yolo11n 20～50 epoch |
| D9–D12 | 模型预标剩余 350 张；人改一天；QC 抽检 |
| D13–D16 | 重训；摄像头实况录误报漏报；专门补这批难例 |
| D17–D23 | 主动学习两轮；指标与误报率对齐业务阈值 |
| D24–D30 | 导出 ONNX；压测；写清「已知失败场景」 |

若中途发现「必须要面积」，再开 **检测框 + SAM** 支线做分割，而不是推翻重来。

## 8. 决策树（复制即用）

```text
只要整图标签？ → 分类
只要知道有没有、在哪？ → 检测
要旋转贴合细长目标？ → OBB
要数个体 + 轮廓/面积？ → 实例分割（优先框+SAM，不要纯手绘）
要路面/天空等区域、不要个体？ → 语义分割（预分割+修）
要骨架动作？ → 姿态（pose 预标+改）
要距离？ → 上传感器/仿真，不要手绘深度
```

## 10. 一句话原则

1. **任务能降级就降级**（分割→检测→分类）  
2. **人只做质检与难例，不做体力描图主力**  
3. **SAM/SAM2 加速轮廓，不替代规范与类别体系**  
4. **没有 Val 精标与 QC，就没有可信模型**  
5. **数据版本化，和代码发布一样严肃**
